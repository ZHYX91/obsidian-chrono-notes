# 日历查询一致性

## 1. 唯一规则

周期笔记查询和依赖收集使用同一个 `resolveIndexedPeriodicNotePath()`，传递完整的 `PeriodicNoteRule`，包括 `pathLocale`。界面语言不是文件路径语言的替代值。相关依赖键包含路径语言；缓存只允许复用与当前查询相同路径的数据。React 构建月、周、年和世纪请求时，memo 依赖也必须包含每种周期的 `pathLocale`、启用状态和格式；修改路径语言后，当前打开的视图立即更新，不依赖翻页或索引事件。

区间列表、日历查询和日历缓存依赖共用 `isIntervalNoteInScope()`。有效的显式 `chrono-notes: interval` 笔记在整个 Vault 内可见；扫描目录只限制未标记的兼容笔记。空扫描目录不排除显式区间。其他显式标记在解析时已经排除，不应重新作为未标记区间纳入。

## 2. 创建与扫描

新建区间笔记会写入显式区间标记。创建目录只须满足现有的创建配置要求，无须位于未标记笔记的扫描目录内。扫描目录为空或尚不存在可以产生诊断，但不能把有效的创建动作替换为设置动作。未配置创建目录仍须引导用户设置。

## 3. 缓存和内存

NoteIndex 是唯一的派生笔记索引。查询缓存仅持有不可变索引条目及依赖引用，不另读 Vault，也不保存第二份笔记事实。NoteIndex 的实时无变化检测保留固定大小的规范文档指纹，不长期保留用于该检测的正文或 frontmatter 字符串。持久缓存只保存可丢弃的派生数据。

`NoteIndexCacheWriter` 串行写入缓存，查询状态由 NoteIndex 独立发布。重启时若缓存全部匹配且无须升级或压缩，则跳过写入。编辑笔记后，Obsidian 适配器只保存受影响的路径。

收到目录通知时，索引会一并处理受影响的 Markdown 路径。移动目录后，如果发现新路径，订阅者在看到旧路径消失时也会看到“索引中”的状态。等待读取的笔记处理完毕后，索引才恢复为“已就绪”。

年视图为每个请求一次性生成网格与规范路径。修改无关笔记时，只需比对这些路径上的索引条目。只有月视图和周视图订阅 ICS 更新。在同一周内选择另一天时复用周查询。日期详情变化时，只要七天的任务索引和用于判断逾期的当天日期都未变化，就可以复用整周任务列表。渲染时对列表分页并保留总数。月视图所选日期详情复用同一查询日。处理中与错误反馈属于按完整任务身份保存的局部交互状态，不能替代索引中的勾选状态或截止日期。

月视图和周视图只为设置中允许显示的区间笔记行分配位置。后续笔记优先使用空出的最上方一行，其余笔记按索引顺序保留在溢出列表中。按月份或年份筛选区间笔记时，以笔记写明的日期为准，包括带时区偏移的时间戳。

## 4. 回归验证

`calendar-query-consistency.test.ts` 将缓存查询的业务值与直接调用选择器的结果比较。版本来源字段不参与业务值比较，其余内容必须一致。测试覆盖非英文路径的各周期类型、持续处于 ready 的修改和删除，以及月／周视图中目录外显式区间的边界修改、移动、删除和标记变化。React 回归保持视图打开并仅修改路径语言，确认月、周、年和世纪视图的笔记状态立即更新。`interval-list-setup.test.ts` 独立验证创建资格不被未标记扫描范围阻止。

完整验证仍需运行 `npm run check`，并在真实 Obsidian 中保持日历打开进行修改、移动和删除，观察预览、统计和甘特条更新。源码测试不替代宿主交互验证。
