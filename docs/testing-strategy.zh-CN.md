# Chrono Notes — 测试策略

## 测试层次

1. Core 单元测试：文档边界、日期算法、路径、任务、统计、ICS。
2. Port 契约测试：NoteSource、NoteIndex、设置迁移和外部 CLI/文件边界。
3. Feature 集成测试：创建笔记、模板、缓存事件、拖拽改期。
4. UI 行为测试：关键选择、打开、弹层和设置依赖；不追求大量脆弱快照。
5. Obsidian 手工验收：桌面、移动、窄侧边栏、主题和插件互操作。

## 关键不变量

- 等价的 BOM/换行/frontmatter 输入产生相同正文状态。
- Vault 最新修订永远不能被较旧异步结果覆盖。
- create/modify/rename/delete 后查询快照最终一致。
- 月视图与年视图统计口径相同。
- 周期路径生成和反向识别互为一致操作。
- 运行时 i18n 的 `auto` 即使在浏览器 locale 不同时也必须读取 Obsidian 公开界面语言 API；未知 Obsidian 语言回退英文。
- 设置归一化不会共享可变默认数组或嵌套配置对象。

每个修复必须先有可复现测试。覆盖率用于发现盲区，不作为替代契约测试的目标。

共享 Markdown 投影回归必须覆盖三/四反引号、波浪线围栏、最多三个前导空格、HTML 注释、同一行与跨行等长 code span、未闭合 inline opener 与后续 fence 的优先级，并证明任务文本保留 code span 内容而日期、预览、字数、链接、标签与嵌入不解释其中语法。设置生命周期必须证明未来 schema 可读但任何保存都在 `saveData` 前失败；首次引导必须证明显示前、显示后、显示前卸载和显示后保存失败四种状态。Templater 契约必须用延迟 promise 证明同一实例的 running-config/parse 临界区不重叠。ICS 契约必须证明来源数、UTF-8 字节数、VEVENT 数与全局读取槽位四个上限，并继续覆盖跨 revision 的迟到结果。

NoteIndex 端口与集成测试固定以下故障模型：去重后的初始路径预留修订并由 16-worker 默认上限读取；worker 共享 8ms 默认时间片并在到期后共同让出一个 host macrotask，确定性注入测试必须证明让步期间不继续启动下一组读取、不发布 staging，恢复后仍只原子合并、发布一次。扫描期间 live 事件立即推进逐路径修订，但普通 create/modify 经 microtask 归约与完成批次发布，不能夹带未越界 initial 结果；delete/rename 必须先形成即时旧路径失效屏障。契约覆盖同修订并发刷新复用、create→modify、create→delete、delete→recreate、A→B→C、跨修订乱序、慢文件不阻塞其他更新、删除期间迟到结果、stop/重启后的迟到结果与 pending 工作丢弃、扩展名变化重命名、`refresh()` 加入正确 promise，以及旧快照保持不变。subscribe、listPaths 或初始化内部抛错必须清除订阅和全部半启动状态，并证明同一实例可再次 `start()`。相同规范文档的 modify 必须只计一次 read/document parse，跳过完整领域派生与公开 publish；error 恢复和 rename 则强制完整解析。投影高基数回归以单批多路径输入固定逐路径最后值获胜、任务 bucket 与区间全序、每个子快照至多推进一次 revision、无变化批次保留 identity，并证明 initial/live commit 都调用同一批量边界。adapter 以结构化假 Vault 固定 `cachedRead()` 边界，不在 core 中引入 Obsidian 运行时。

索引诊断契约使用可注入的单调时钟与墙上时钟固定全量及增量的完成时间、非负耗时、影响路径数和待处理工作数。后台缓存核对不得覆盖最近实时增量指标，诊断订阅必须与日历快照订阅隔离。设置 DOM 测试固定详情默认折叠、无文件名/路径、状态与诊断订阅都在 section 清理时释放；实现不得为显示诊断而追加 Vault 枚举或文件读取。

readiness 回归还必须固定：初始完成前为 `indexing`，原子启动边界后为 `ready`，后续未知路径事件波次先恢复 `indexing`，且只有可注入的安静 checkpoint 看到 pending intent、读取、队列和 batch 全部为空后才恢复 `ready`。Calendar store 测试证明只改变 readiness 的快照会把可见未知周期路径从 missing 重新计算为 indexing，而不重新物化 notes，已有 parsed/error entry 语义不变。呈现测试区分弱化色虚线索引标记与错误色不存在标记，并在未知时使用中性的“打开或创建”菜单文案；命令验收必须证明 indexing 状态仍进入周期笔记用例，而文件端口存在性检查继续保证已有文件直接打开、缺失文件才创建。

持久化缓存契约使用可提供元数据的 fake source，以及可注入的缓存与调度器。测试必须证明：`path + mtime + size` 匹配项在任何校验读取前恢复；元数据变化或启动事件触碰的路径在 `ready` 前读取；已删除路径不读取并直接消失；损坏快照清理后回退到完整初扫；缓存写入合并且绝不包含源文档或 frontmatter。快照与条目数 sidecar 必须在当前 Vault 的同一个事务中保存和清除；状态检查只读 sidecar，旧缓存则用轻量 `getKey()` 检查存在性并由下一次正常保存补齐元数据。显式重建必须等待 ready 且 idle 后的即时保存完成，保存失败向上传播，不能把过时的 empty 状态报告为成功。缓存深度校验与后续完整读取校验都必须复用初扫 8ms host 时间片。后台校验必须从后续 host task 开始、修正相同元数据下的外部修改、派生值未变时不发布，并主动让位给待处理或进行中的实时修订。schema 非法、路径重复、元数据非有限数、区间日期键非法、区间边界或天数与规范重解析结果矛盾、路径/任务不一致和任务统计矛盾都必须使快照失效。任务日期标记字符串有意保持冷解析语义，非法公历日期由日期投影忽略，不因其存在而让整份可复用缓存失效；IndexedDB 缺失与存储错误必须 fail-open。暖缓存基准记录恢复条目数、快速 ready 前读取数和是否已安排完整校验，不得把快速 ready 描述成取消了后续 I/O。

缓存维护契约必须把 IndexedDB 不可用、当前 Vault 无记录、有效已存储记录、条目数未知的旧版记录、无效 sidecar 和读取错误分开，不能把“空”误报为“不可用”。删除范围以当前 Vault 的名称与存储 identity 组成的精确键为边界，测试证明其他 Vault 和其他 IndexedDB 键保持不变。生命周期回归必须覆盖重复重建、并发请求合并、清除失败后仍恢复索引与源订阅、即时保存完成后才刷新 stored 状态、保存失败可见、首次重启失败后单次恢复重试、连续重启失败的可见错误，以及卸载或运行时替换发生在清除期间时旧实例不得复活；按钮订阅也必须在设置 section 清理时释放。

实际 `ObsidianNoteSource` 与可控 fake Vault 的组合回归让 `cachedRead()` 乱序完成，分别覆盖 initial→modify、pending modify→rename 和 pending modify→delete，证明较新结果发布或旧路径失效后，旧读取不能覆盖或复活。该测试只固定 adapter 事件映射与 NoteIndex revision 屏障，不能证明真实 Obsidian 内部缓存对外部同步的失效时序；桌面和移动端快速修改/同步仍是人工发布门禁。`refresh()` 遇到 queued missing 时先提交删除屏障，再以新 revision 执行显式重读；测试固定 listener 先看到 missing，再看到该重读的 parsed 或 error 终态。

设置契约逐项覆盖 Chrono Notes schema v1–v18 的顺序迁移、无版本与非法版本按 v1 处理、未来版本不降级、已有合法值保留、未知字段最终剔除、重复迁移幂等，以及输入、默认数组和嵌套对象不共享可变引用。schema v15 必须证明共享确认字段被删除、不映射旧值，周期与区间两个严格布尔开关独立归一化；schema v16 必须证明旧待办标注的 `none` 映射为关闭、`color` 与 `hole` 映射为开启，删除旧字段，并严格归一化新的布尔值；schema v17 使用真实已发布 schema v15 形态的夹具，证明有序 `calendarOverlays` 迁移为 `calendarExtensions`，五类文档化 Luxon 周期路径转换为 Moment，模板及无关的节假日/ICS 值保持不变，合法 Moment 与无法识别的自定义格式不被改写，两个旧字段被删除，并让五种 Note Navbar 重新识别既有路径；schema v18 证明旧配置新增日期/时间 `system` 选择与合法的自定义默认 pattern，且已有合法四字段不被替换。真实 Obsidian 验收向隔离 Vault 注入代表性旧版本与非法数据，完整重载后检查五个设置 tab 的保留/回退，再保存为当前 schema 并证明数组配置互不串改。

周期笔记命令测试覆盖未配置、已有文件、创建确认、统一锚点模板上下文、父目录创建、内置模板目标日期、创建前模板失败不产生文件、Templater 延后渲染失败后保留已创建目标、级联跳过/失败/继续，以及打开视图失败不删除成功文件。内置模板必须断言最终正文只进入一次 `create` 且不调用 `finalize`；同一路径并发回归必须让创建/模板保持一次，证明首请求与等待者的 `created` 结果、各自 open target 和各自 cascade 不串联，并固定失败后可重试。Obsidian 文件端口另以周期与区间两个实例同时创建同一公共父目录，证明只调用一次 `createFolder`、两份笔记都成功；注入失败后必须清除共享 promise 并允许下一次重试，外部参与者在竞争期间完成目录创建时也应重新检查后成功。共享确认编排契约必须证明取消不保存、未选中时确认不保存、只有选中“不再确认”并确认创建才持久化，并且级联不重复调用确认。Obsidian adapter 用结构化 Vault/Workspace 测试事件边界，人工验收再覆盖真实 Modal、命令面板和主题行为。

生命周期契约要求已有的旧 schema 设置在启动时写回规范化的当前 schema 快照；同时必须保持 fail-open：写入被拒绝时仍使用已迁移的运行时设置，并记录原始错误。

周期设置呈现契约覆盖空值、不支持的 token、无法往返识别的格式、文档列出的 Obsidian/Moment 子集、方括号固定文字、运行时对已移除 Luxon 路径语法的拒绝，以及五类完整路径共用的 `diary` 目录体系。独立迁移契约只转换文档化的 Luxon token 与单引号字面量一次，不增加第二套运行时解析器。直接格式化/反向识别固定日记 `[diary]/YYYY/YYYY-MM/YYYY-MM-DD`、周记 `[diary]/GGGG/GGGG-[W]WW`、月记 `[diary]/YYYY/YYYY-MM`、季记 `[diary]/YYYY/YYYY-[Q]Q` 和年记 `[diary]/YYYY`，并覆盖周日起始 ISO 跨年预览、Vault 路径分隔符、嵌套文件夹及文件夹方括号转义。内置模板契约固定复用同一日期/时间编译器、`ddd`/`dddd` 按 locale 输出、区间 `start`/`end`/`days` 占位符，以及不支持的 placeholder 原样保留。结构契约固定带名称的“周期笔记”tab panel 内“周期笔记行为”“周期笔记路径”和五种周期类型全部使用 Obsidian 原生三级标题；每个已启用类型在本章内依次拥有路径格式与模板路径。“区间笔记”在创建目录旁配置模板路径，“常规”则用一个“模板设置”三级标题承载引擎及对应语法说明。源码边界固定禁用周期类型先收起路径、文件夹与 Markdown 模板均使用 Obsidian 原生键盘建议、路径校验暴露 `aria-live` / `aria-invalid` 并关闭自动大写、模板来源只调用 `getMarkdownFiles()`。真实 Obsidian 验收补充鼠标与键盘候选选择、完整相对路径写回、实时预览/错误、保存重载、全部受支持 UI 语言和窄设置面板。

- publish job 的内联 Python ZIP 验证器是候选解压的唯一信任边界，且测试直接从 workflow 提取并执行同一段代码。它在读取或提取任何成员前拒绝外层 Actions artifact ZIP 的目录、额外/缺失/重复项、非规范/绝对/回退/反斜杠/NUL/控制路径、加密项与 symlink/非普通文件；仅在精确五项验证通过后逐文件安全提取，并严格验证四行 `SHA256SUMS`。内层手动安装 ZIP 也须先证明恰含按固定顺序排列、模式为 `100644` 的三个普通文件，再直接与 loose assets 逐字节比较。恶意 ZIP 回归测试覆盖上述路径、类型、重复、加密、错误模式与错误 checksum 边界，不以 workflow 字符串存在断言代替执行证据。
- 外层和内层 ZIP 都固定单项 8 MiB、总解压 24 MiB 的元数据预算，并在读取内容前拒绝超限候选。外层允许 GitHub artifact 使用非 Unix/DOS 普通文件元数据，因为精确 ASCII 清单已固定目标且只逐项写入已知普通文件路径；目录位仍被拒绝。执行型 checksum 样本分别固定缺失、重复、额外、乱序和 digest 错误均 fail closed。
- 标签触发的 existing same-tag no-op 完全在只有 `contents: read` 与 `attestations: read` 的 verify job 闭环；四附件字节、逐项精确 provenance 与最终 tag→commit 复核任一不符都失败。只有 `release_exists == 'false'` 才运行 release-notes、candidate staging、artifact upload 和整个 write-token publish job。数字稳定版本标签 ruleset 与 Release immutability 均为管理员外部前置：update/delete 都受限，实际 release actor 无 bypass；自动门禁只记录该要求，不修改 GitHub 设置。
- workflow ZIP 验证器及执行其原样源码的本地完整测试要求 Python 3.9 或更高；内联源码在导入其他验证逻辑前检查版本，较旧解释器清晰 fail closed。
- `npm run bench:quick` 与 `npm run bench:large` 分别生成 1,000/10,000 篇确定性内存数据，记录 opt-in 的 list/read/document-parse/note-derivation/initial/live-commit/materialize/notify 阶段计时，以及 month/week/interval/year/heatmap、农历双扩展与 `Intl` 双扩展的冷/热月装饰、事件风暴、多订阅者和 ICS 状态/内容变化；计时报告 p50/p95/max。8/16/32 初扫矩阵使用受控释放并硬性比较峰值并发、逻辑完成轮次、在途内容量、单路径读取、初始发布次数，并深比较排序后的完整 note entry、task date bucket 与 interval 投影语义，不以聚合数量或墙钟代替正确性。单文件更新 guardrail 在两种规模下反复修改同一篇普通笔记：每次已结算更新固定 1 次读取、1 次物化、1 次发布与 1 次通知，计时统计只包含这些更新样本；p95 更新延迟预算为 1,000 篇 100ms、10,000 篇 250ms，snapshot 物化预算为 10/50ms，通知预算为 25ms；`--expose-gc` 可用时 GC 后 retained heap 增量上限为 64/128 MiB。CI 和发布门禁除快速基准外，还通过 `npm run bench:single-file:large` 单独执行 10,000 篇场景；这些阈值只用于稳定环境捕获数量级退化，不是精确剖析承诺。process `heapUsed` 只是可选 GC 下的 best-effort 同机线索，不能冒充真实宿主 heap snapshot；读取次数、发布次数、最终路径每批最多一次 read、访问 bucket 数和产物大小才适合硬门禁。
- `npm run holiday:check` 检查当前年与下一年，要求每个 release verdict 都有一手来源核验记录；当年缺失、下一年已发布但未补齐、未核验或状态矛盾以非零状态退出，下一年官方尚未发布则保留 unavailable、输出警告并返回成功。`npm run release:check` 串联自动代码门禁、双时区、快速基准、10,000 篇单文件更新门禁和该节假日门禁；它不代替真实 Obsidian、真实移动端、React Profiler、长任务或 heap snapshot。发布说明必须如实区分自动证据、针对性真实宿主回归和未取得的设备或性能证据。

## 可再生验收 Vault

桌面与 Android 模拟器验收使用同一套自动生成的确定性 Vault。`npm run acceptance:vault:create` 先构建当前生产产物，再在系统临时目录的 `chrono-notes-acceptance/<run-id>/` 下生成唯一 Vault；生成内容包括五类周期笔记、正文与仅 frontmatter 状态、任务进度、调休组合、三条重叠区间、全天/定时/跨日/重复 ICS、多语言历法参考文本，以及周期与区间内置模板创建 canary。夹具关闭创建确认、开启较大周期级联，并把全部周期类型指向同一确定性模板，使桌面和模拟器都能从一次日记创建同时检查目标日期渲染、未知占位符保留、已启用上级周期创建及既有上级笔记不覆盖。默认启用太阳希吉拉历与乌姆库拉历以覆盖多个非公历 provider。`.obsidian` 只启用 Chrono Notes，并部署当前构建的 `main.js`、`manifest.json` 与 `styles.css`。

每个生成目录都有专用标记和逐文件 SHA-256 清单。`npm run acceptance:vault:verify -- --target <path>` 检查标记、生产版本和所有预期文件；夹具与插件产物仍按字节严格核验，Obsidian 管理的 JSON 改按语义核验，以允许宿主重写格式。核心插件的必需值不得改变，但允许宿主补充自己管理的键。Obsidian 可以增加自己的工作区文件，但不得静默改变生成夹具、插件设置或插件产物。`npm run acceptance:vault:clean -- --target <path>` 只允许删除指定临时根目录下、不是符号链接且带有效标记的单个 Vault。每次创建前还会清理超过七天且满足相同安全条件的残留；无标记目录和根目录外路径始终跳过。失败 Vault 可以暂留诊断，验收闭环成功后必须显式清理。

固定的用户 Vault、OneDrive Vault、私有 ICS、个人设置和旧工作区不得作为生成输入或提交进仓库。桌面与 Android 必须部署同一个已验证生成目录；模拟器传输、真实 UI 操作、日志采集和结果判定仍属于宿主验收，不因夹具可再生而宣称已自动化。

## 人工发布门禁

仓库自动门禁通过不等于真实宿主行为已经验证。每个发布候选必须记录执行日期、Obsidian 版本、操作系统、主题、窗口或侧栏宽度、三个安装文件的哈希、结果和缺陷链接，并在同一候选产物上完成与本次变更相关的真实宿主回归。

以下完整矩阵按风险触发：

- `minAppVersion`、Obsidian API/DOM adapter、生命周期、设置页或主要视图交互变化时，在最低支持的 Obsidian 1.12.7 与执行时最新稳定桌面版中重跑相关完整停用/启用、重载和卸载矩阵；次版本发布前重跑完整桌面矩阵。
- 主题变量、响应式布局、键盘/ARIA、焦点或弹层变化时，在默认浅色、默认深色和至少一个第三方主题下覆盖主区域与约 300–360 px 窄侧栏；未改动的视觉表面不要求补丁版本机械复验。
- 安全区、周期 Note Navbar、触摸、粗指针、横竖屏或软键盘变化时，在可用的真实移动设备上记录对应矩阵。物理设备证据始终作为单独报告的可选结论，缺失时不阻断共享发布闭环；不得把模拟器证据表述为真机通过。
- NoteIndex、查询、缓存、解析、依赖或 bundle 预算发生性能相关变化时，在可再生的 1,000/10,000 篇真实宿主 Vault 上记录安全入口可用、元数据安全的快速 ready、后台逐字节校验完成、最长主线程任务、read/parse/publish、React render/commit、缓存体积、heap 起点/峰值/稳定值和 stop 后回收量。冷启动与暖启动必须在同机比较，不设置跨机器绝对毫秒阈值；没有 Profiler 证据不引入 `React.memo`。

未触发或未取得的证据限制对应兼容性、真机或性能结论，不阻止与该表面无关的补丁发布；文档和发布说明不得把缺失证据写成已经验证。

## 节假日年度维护

节假日发布数据只接受国务院办公厅、中国政府网政策文件库、新加坡人力部或政府公报等一手来源，不使用搜索摘要、商业日历或推算结果。当前 provider 覆盖中国大陆与新加坡；发布检查始终滚动检查运行时当前年与下一年。

1. 运行 `node scripts/check-holiday-coverage.mjs`，需要指定年度时使用 `--year YYYY`。
2. 每次核验同步更新 `holiday-coverage.ts` 中的官方发布状态、核验日期和一手来源。`unverified`、`available + not-published`、当前年缺失、下一年已发布但数据未补齐都必须阻断；下一年经一手来源确认尚未发布时保持 `unavailable` 并警告通过。
3. 官方安排发布后，同一变更必须补齐 provider 日期、调休上班或依法顺延、普通覆盖日、未覆盖年、三语名称、递归冻结测试和发布状态，不能只改 coverage 或只改状态。
4. 运行对应 provider 测试、`npm run holiday:check`、`npm run check` 和 `npm run release:check`。

当前数据状态由 `npm run holiday:check` 的输出与源码记录共同决定，不在稳定文档硬编码将来会过期的测试数量。现有门禁预期新加坡当前年与下一年可用；中国大陆下一年仅在一手来源确认正式安排尚未发布时允许以带来源警告的 `unavailable` 状态继续，绝不预测。

## 日历布局几何

源码 CSS 契约须固定周序号四角均为与日期格一致的 `5px` 圆角，不得只断言左侧圆角或保留右侧直角；同时固定季度/月状态槽为 `top: 4px`，并保留标签居中与入口格高不变的规则。人工计算几何复核再确认圆点与标签形成约 `2px` 可见间距，并在主区域、窄侧栏和深浅主题下比较有/无状态时标签中心与格高不变。

工具区到主内容的 CSS 几何契约须按视图区分：月视图保留工具区底部 `4px`、`24px` 星期表头和表头到日期网格 `6px`；周视图与年视图则从完整工具区底边到首个主内容格或区块形成 `8px` 有效间距，包括热力工具在窄宽换行后的状态。源码/DOM 回归须同时拒绝空白或伪星期表头，并证明日期格、周期入口和热力格的内部 padding、gap 与高度未被用作间距补偿。人工验收在主区域与窄侧栏、月/周/年、概览/热力模式及工具组换行前后测量上述边界，并确认内容密度和卡片内部几何保持不变。

月日期按钮自身必须声明显式全宽单列，不能依赖会受宿主按钮对齐影响而收缩的隐式 auto 列；后代节假日或 ICS 文字不得改变顶部行宽度或任一锚点。几何验收须在等宽格中比较“班（下方无节假日名）/休（下方有节假日名）/公假（多字标记）”和圆点/任务进度，并覆盖主区域、`360px` 与 `240px` 容器：左右锚点误差不超过 `1px`、间距至少 `4px`，进度只收缩右端，极窄格的多字标记可省略但不得溢出；深浅主题均须目测复核。源码级 CSS 断言用于守住布局契约，但不能替代真实计算几何验收。

## 性能回归补充

- 农历语言适配测试固定同语言零次 `setLanguage()`、跨语言切换与恢复、同/跨语言嵌套、操作抛错、操作内部改写全局状态以及简中/繁中/英文连续调用；冷月装饰基准必须继续覆盖默认农历与大陆/新加坡节假日组合。
- live event batch 在 `readConcurrency: 4` 下覆盖 4、5、8、64 条快速路径，证明读取槽可继续排空而发布 promise 保持等待，并在注入的 checkpoint 触发后只发布一次。慢项回归允许 checkpoint 与最终稳定边界各发布一次；错误、no-op、旧修订、delete/rename 屏障和 stop/restart 取消继续单独固定。
- 事件风暴基准必须等待每条相关 `refresh()` promise，而不是只轮询计数；报告先输出再执行最终门禁。10,000 条模式固定每个 create/modify 批次每终态路径一次读取、快速 32 路批次一次发布。
- 生产产物明细同时输出预算余量、相对记录基线的总增量、按依赖包聚合和最大单输入。任何门禁放宽或依赖替换都必须解释当前 `npm run size` 输出，并保持语义、移动端兼容和产物 smoke test。
- 启动性能人工记录必须区分安全入口可用、元数据安全的快速 ready 与后台逐字节校验完成，并记录各里程碑读取数、最长主线程任务、缓存体积和 heap。任何把暖启动快速 ready 写成取消后续完整校验的说明都属于发布阻断错误。
